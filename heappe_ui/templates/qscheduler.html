    QScheduler Instances

    A QScheduler instance (quantum task scheduler) can be shared by several HEAppE instances. Assign a HEAppE instance to let it reach the QScheduler and, optionally, receive task and session notifications through its own QScheduler notifier. QScheduler features require HEAppE 6.6.0 or newer; older HEAppE instances cannot be assigned. Quantum machines are added per HEAppE instance on the Clusters page.

    Deploy QScheduler Instance

    Starts qscheduler serve on this Docker host with its own PostgreSQL (or an existing database) and a Docker healthcheck. Machines are added later from the Clusters page.

    Image
    Service
    -<random id>
    A random id is always appended, e.g. qscheduler-5190156f: it is the instance and container name and the host name HEAppE uses.
    Binds 127.0.0.1 only.
    Subnet of the internal <name>_db_net, taken from QSCHEDULER_NETWORK_POOL. Two containers use it (QScheduler and its or the shared PostgreSQL).
    Creates role and schema qs_<name> in the shared database; only this instance can use it.
    Assignment
    HEAppE 6.6.0 or newer.
    Register Existing QScheduler
    QScheduler 0.2.1+: admin API inside the container (its ADMIN_TOKEN); older: docker exec <container> qscheduler ... and docker restart.
    The container must run an SSH server. Commands run as qscheduler ... inside it.
    {% include 'partials/qscheduler_sshc_warning.html' %}
    The server's host key is pinned on registration and checked on every later connection.
    Before QScheduler 0.2.1, new machines and notifiers need a service restart (0.2.1+ is managed over its admin API, no restart). The default sends SIGTERM to PID 1 (graceful shutdown) and relies on the container's restart policy. Leave it empty to restart manually (the instance is then marked "restart pending").
    QScheduler 0.2.1+ is managed only over its admin API. Leave empty to take it from the container environment; when another HEAppE Management already manages this QScheduler, copy it from there (Actions → Admin token... → Show).
    Update QScheduler Instance
    Recreates the container with the same configuration (database, networks, ports); for git the image is rebuilt on the instance's Docker host. Machines, notifiers and projects are kept in PostgreSQL. If the new version is not healthy, the previous container is restored.
    Assign HEAppE Instance
    {% include 'partials/qscheduler_sshc_warning.html' %}
    For a QScheduler on this Docker host, its container joins the HEAppE API network (the HEAppE API restarts briefly). A remote QScheduler must be reachable from HEAppE at its configured host and port.
    Every cluster of this HEAppE on this QScheduler gets its own notifier <identifier>.<machine> with its own token, created when the cluster is added on the Clusters page. The token is always stored in HEAppE Vault. Changing these settings recreates the notifiers of existing clusters with new tokens. When off, HEAppE polls task state.
    HEAppE TaskCallback endpoint as reachable from the QScheduler host.
    {% include 'partials/qscheduler_sshc_warning.html' %}
    Backups –

    Database dumps (pg_dump custom format, checked with pg_restore --list) in on the host. The in-place update creates one automatically and restores it on rollback.
