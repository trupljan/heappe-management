Deploy QScheduler Cluster?

This action deploys a QScheduler service (quantum task scheduler) in Docker, registers a quantum machine in it, and fully configures the matching QScheduler cluster in the selected HEAppE instance. One HEAppE cluster corresponds to one QScheduler machine; one QScheduler instance can serve many machines.

What exactly does this process do:
1. Build Docker Image

Builds qscheduler:latest from the QScheduler git repository (Rust release build on Debian slim). An existing image is reused unless a rebuild is requested.

2. Start Database & Service

Starts a private PostgreSQL 16 container on an internal network, registers the machine (test simulator or iqm backend) and runs qscheduler serve as qscheduler-{id} with a Docker healthcheck.

3. Connect to HEAppE

Joins the HEAppE instance's Docker network, restarts the HEAppE API so it picks up the change, and verifies /health from inside the HEAppE container.

4. Register in HEAppE

Creates the Cluster (HTTP), File Transfer Method, QPU Queue Group with accounting formula, a Queue for the machine and a QPUSeconds Project with optional allocation. A callback token is generated and set in both QScheduler and HEAppE.

The next dialog can also add a machine to an existing instance, update an instance from git, or undeploy it.

Important Note: Make sure the Docker daemon is running. The first image build compiles QScheduler from source and can take several minutes. The HEAppE API is restarted briefly when QScheduler joins its network. You can monitor or stop the containers later in the Deployments tab.
QScheduler Cluster

Each HEAppE cluster maps to one QScheduler quantum machine; one QScheduler instance can serve many of them. This registers the machine, creates the HEAppE cluster, queue, project and QPU allocation, and, for a new instance, deploys the QScheduler service with its own PostgreSQL in Docker.

The instance is restarted to load the new machine; tasks running on its other machines are interrupted briefly.
